# Размещение frukt116

Проект: `C:\Users\User\Documents\GitHub\RE`.
Нужен Node.js 24. Страницы, видео и API обслуживаются одним процессом.

## Локальная работа

`npm.cmd run dev` — сайт на http://localhost:5173 и API на 127.0.0.1:3001.
`npm.cmd run build` — сборка.
`npm.cmd run check` — TypeScript, синтаксис JS, соответствие каталогов, цены, фото и видео.
`npm.cmd test` — расчёты заказов, ошибки ввода, повторы запросов, база и серверные маршруты.
ESLint пока не настроен; `check` не является ESLint.

## Сервер

Установка: `npm ci` (включая devDependencies для сборки).
Сборка: `npm run build`.
Запуск: `npm start`.
Переменные в панели хостинга: `NODE_ENV=production`, `HOST=0.0.0.0`, `PORT=8080` либо порт хостинга.
Служебная проверка доступности: `/api/health`.
Прокси должен направлять и страницы, и `/api` к одному процессу. Подключите HTTPS.
`TRUST_PROXY=1` подходит только для ровно одного доверенного прокси: не используйте его без проверки схемы хостинга.
Локально `.env` не загружается автоматически; переменные задаются в окружении процесса.

## Постоянное хранение заказов — обязательно

Заказы сохраняются в SQLite, по умолчанию `storage/orders.sqlite`.
На хостинге обязательно подключите постоянный диск и задайте `ORDERS_DB_PATH`, например `/data/orders.sqlite`.
Временная файловая система App Platform или контейнера без диска НЕ подходит: обновление сервиса уничтожит базу.
Если выбранный тариф не поддерживает постоянный диск, используйте VPS с постоянным диском либо замените SQLite на внешнюю базу до запуска.
Папка базы должна быть доступна процессу на запись и находиться вне `public` и `dist`.
Запускайте один экземпляр приложения с этой базой; для нескольких экземпляров нужна внешняя база.
Заказы и контакты исключены из Git и Docker-образа. База не отдаётся посетителям.
Просмотр последних 50 заказов владельцем на сервере: `npm run orders`.
Автоматические уведомления владельцу ещё не подключены. До их подключения проверяйте список заказов; посетителю предложено связаться с магазином для подтверждения.
Для резервной копии остановите процесс и скопируйте всю папку базы вместе с возможными `-wal` и `-shm` файлами. Не копируйте только основной SQLite-файл работающего сервера.

## Docker (подготовлен, но сборка образа здесь не проверялась)
 
Панель владельца: `/admin`. Первый вход: `npm run admin:link` выдаёт личную одноразовую ссылку для создания пароля (12–128 символов). Не пересылайте её. Для хостинга задайте `ADMIN_URL=https://ваш-домен/admin` перед этой командой. В production обязателен HTTPS для cookie входа; при необходимости за прокси задайте `PUBLIC_ORIGIN=https://ваш-домен`.

SQLite теперь содержит также товары, загруженные фотографии и данные входа. Переносите базу на сервер и сохраняйте резервные копии, чтобы не потерять местные изменения. Начальный `shared/catalog-seed.json` не перезаписывает правки владельца при запуске. `owner-setup-token.txt` рядом с базой — секрет, удаляемый после первого входа. Панель редактирует существующие товары; добавление новых пока не предусмотрено.

`docker build -t frukt116 .`
`docker run -d --name frukt116 --restart unless-stopped -p 8080:8080 -v frukt116-orders:/data frukt116`
Здесь именованный том `frukt116-orders` сохраняет заказы при пересоздании контейнера.
Просмотр заказов: `docker exec frukt116 npm run orders`.
Не удаляйте том при обновлении. HTTPS подключается перед контейнером.
